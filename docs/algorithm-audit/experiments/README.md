# ניסוי השכנות המורחבת — קוד והרצה

ניסוי בלבד. שום קובץ כאן אינו חלק מהאפליקציה, ושום קובץ תחת `src/`, `server/` או `tests/` לא שונה.

קומיט הבסיס: `c7247a3`. הדוח: `../extended-neighborhood-benchmark.md`.

## הקבצים

| קובץ | תפקיד |
|---|---|
| `scenarios.js` | עשרת התרחישים הקבועים ושלושת תרחישי הביקורת: סל + פרופיל לכל אחד |
| `extendedNeighborhood.js` | עותק של חיפוש המתכנן (`src/lib/weeklyPlanner.js`) עם שכנות ניתנת להחלפה: `baseline`, `swap`, `pair`, `extended` |
| `metrics.js` | מדידות על התפריט הסופי, בעזרת הוולידטור והמסווג של האפליקציה |
| `runBenchmark.js` | המריץ: איכות, זמני ריצה, שחזוריות; כותב את `results.json` |
| `vitest.config.js` | תצורת הרצה נפרדת, עם אותו כינוי `@/` → `src/` |
| `feasibilityCheck.mjs` | עזר לתכנון התרחישים: מריץ את מתכנן הייצור בלבד |
| `results.json` | התוצאות, קריאות למכונה |

## איך מריצים

מתיקיית השורש של המאגר:

```
npx vitest run --config docs/algorithm-audit/experiments/vitest.config.js
```

ההרצה המלאה (10 תרחישים, 4 הרצות איכות ו-22 הרצות תזמון לכל אחד) נמשכת כמה דקות. אין צורך בשרת, ברשת או בקטלוג.

משתני סביבה אופציונליים:

- `BENCH_TIMING_RUNS=0` — איכות בלבד, בלי תזמון
- `BENCH_ONLY=S01-omnivore,S04-vegan` — תרחישים מסוימים
- `BENCH_OUT=./other.json` — קובץ פלט אחר

בדיקת ההיתכנות של התרחישים (מתכנן הייצור בלבד):

```
npx vite-node docs/algorithm-audit/experiments/feasibilityCheck.mjs
```

`npm test` אינו מריץ את הניסוי: שם המריץ אינו מכיל `.test.`, ולכן תצורת הבדיקות של הפרויקט אינה אוספת אותו.

## מה מקוד הייצור נמצא בשימוש חוזר

ללא שינוי, מיובא ישירות מ-`src/lib/`: `nutritionPlanGenerator.js` (`generateNutritionPlan` — הצינור כולו), `weeklyPlanner.js` (`planWeek` — הבסיס), `menuCandidates.js`, `mealScoring.js`, `mealPlanCalories.js`, `mealPlanRules.js`, `mealPlanBudget.js`, `validateMenu.js`, `shoppingOptimizer.js`, `pricing.js`, `calculations.js`, `weekDays.js`; וסלי הבדיקה מ-`tests/fixtures/`.

מה שהקוד הניסויי משנה: רק את מה שקורה אחרי שהחיפוש המקומי של הייצור התכנס — נוספים מהלכי החלפה בין ימים והחלפה מתואמת של שתי משבצות. קוד הייצור אינו משתנה, לא בדיסק ולא בהתנהגות האפליקציה.

## איך מובטח שרק השכנות שונה

- המריץ קורא ל-`generateNutritionPlan` **של הייצור**. מועמדים, פונקציית המטרה, המשקלים, ארבע הגרסאות, האיזון, ההתאמה לתקציב, הוולידטור ובחירת השבוע הם קוד הייצור עצמו.
- רק המודול שממנו מיובא `planWeek` מוחלף בזמן ההרצה (`vi.mock`). במצב `production` התחליף מעביר את הקריאה ל-`planWeek` האמיתי.
- `extendedNeighborhood.js` מעתיק את הבנייה החמדנית ואת החיפוש המקומי שורה אחר שורה. לפני כל השוואה המריץ בודק, לכל תרחיש ולכל אחת מארבע הגרסאות, שהעותק במצב `baseline` מחזיר בדיוק את השבוע ואת ערך המטרה של `planWeek` האמיתי (`replicaEqualsProduction` בתוצאות).
- המהלכים הנוספים מופעלים רק אחרי שהחיפוש של הייצור התכנס, ולכן ערך המטרה של `extended` לעולם אינו נמוך משל הבסיס.
- המריץ רושם את `git status` של `src/`, `server/` ו-`tests/` לפני ואחרי (`productionUnchangedDuringRun`).

## הרחבה ל-100 תרחישים (12.10.2026)

הניסוי הורחב מעשרה תרחישים ל-100: עשרת המקוריים ועוד 90 תרחישים סינתטיים. `results.json` של עשרת התרחישים לא שונה. קומיט הבסיס של ההרצה: `d756073` (קוד הייצור זהה ל-`c7247a3`).

| קובץ | תפקיד |
|---|---|
| `buildScenarios100.mjs` | מחולל התרחישים הסינתטיים, בעל זרע קבוע (`SEED = 20261012`, mulberry32) |
| `scenarios100.json` | 90 התרחישים שנוצרו (`scenarios`) ותיאור המערך (`meta`) |
| `results-100.json` | התוצאות הגולמיות של 100 התרחישים, קריאות למכונה |
| `analyze100.py` | חישוב מדדי הסיכום מתוך התוצאות הגולמיות |
| `summary-100.json` | מדדי הסיכום שעליהם נשען ספר הפרויקט (סעיף 5.7, טבלה 5.2, איור 5.4) |

### איך נוצרו התרחישים

- **רשת תכנון מלאה 3×3×3:** מטרה (ירידה, שמירה, עלייה) × גודל סל (דל 9–12, בינוני 14–20, עשיר 22–30 מוצרים) × רמת תקציב חודשי (צפוף 1,200–1,500, רגיל 1,600–2,200, נדיב 2,400–3,400 ש"ח).
- **העדפת תזונה במכסה קבועה:** ללא העדפה 36, צמחוני 14, טבעוני 12, ללא לקטוז 9, ללא גלוטן 9, כשר 10.
- **פרופיל:** נתוני גוף אקראיים, שמהם נגזרים היעדים בנוסחאות האפליקציה (`calculateBMR`, `calculateDailyCalories`, `calculateMacros`); בכ-30% מהתרחישים אלרגיה אחת, מזונות לא אהובים או מזונות אהובים.
- **סל:** נדגם מ-38 מוצרי קטלוג הבדיקה (`tests/fixtures/baskets.js`), עם גרעין מובטח של מוצרים שהפרופיל יכול לאכול ותוספות; חלק מהסלים כוללים במכוון מוצרים שהפרופיל אינו יכול לאכול.
- **כלל קבלה, שנקבע לפני ההשוואה:** מועמד מתקבל רק אם צינור **הייצור** בונה עבורו שבוע שלם. האלגוריתם המורחב אינו משתתף בהחלטה. 27 מועמדים נדחו והוחלפו בהגרלה הבאה.
- **ללא כפילויות:** 90 תרחישים שונים ו-90 סלים שונים (דמיון Jaccard בין סלים: חציון 0.31, מרבי 0.93).

אלה תרחישים סינתטיים ולא נתוני משתמשים אמיתיים, והם תובעניים במכוון: 59 מ-100 מדורגים כבר בבסיס ברמת איכות 3.

### שחזור

מתיקיית השורש של המאגר:

```
npx vite-node docs/algorithm-audit/experiments/buildScenarios100.mjs
BENCH_SET=100 BENCH_COMPACT=1 BENCH_TIMING_RUNS=5 BENCH_OUT=./results-100.json \
  npx vitest run --config docs/algorithm-audit/experiments/vitest.config.js
python3 docs/algorithm-audit/experiments/analyze100.py
```

- `BENCH_SET=100` — עשרת התרחישים המקוריים (`kind: "original"`) ו-90 הסינתטיים (`kind: "synthetic"`); תרחישי הביקורת אינם מורצים.
- `BENCH_COMPACT=1` — התפריטים המלאים ודוגמאות המהלכים אינם נשמרים, כדי שקובץ התוצאות יישאר קטן.

המחולל דטרמיניסטי: הרצה חוזרת מפיקה קובץ זהה. ההרצה המלאה נמשכה כ-28 דקות (Apple M1 Pro, Node 22.21, סביבת Node של vitest).
