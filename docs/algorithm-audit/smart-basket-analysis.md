## התשובה הקצרה

הסל החכם הוא **בנייה חמדנית מונחית-מכסות**: רשימה קבועה של "צרכים שבועיים" נסרקת בסדר קבוע, ולכל צורך שעדיין חסר נבחר המועמד בעל הניקוד המשוקלל הגבוה ביותר מבין אלה שנכנסים בתקציב שנותר. לפני הבחירה יש סינון קשיח, ואחריה רשת ביטחון של מוצרי יסוד, השלמת חלבון חמדנית וגיזום חמדני כשהסל חורג מהתקציב.

אין פונקציית מטרה לסל כולו, ולכן זה אינו אלגוריתם אופטימיזציה במובן המדויק אלא היוריסטיקה קונסטרוקטיבית. הבעיה עצמה היא שילוב של שלוש בעיות:

- **דירוג** — בתוך כל צורך;

## 4.3 פונקציית הניקוד

```
candidateScore = 0.30·nutrition + 0.25·health + 0.20·history + 0.15·price + 0.10·variety
```

המשקלים נקראו מ-`WEIGHTS` ב-`smartBasketEngine.js`. כל רכיב בטווח 0..1, והתוצאה מעוגלת ל-3 ספרות.

| רכיב | משקל | חישוב | טווח | משמעות |
|---|---:|---|---|---|
| `nutrition` | 0.30 | תלוי בצורך. חלבון / חלבי / בוקר: `min(1, חלבון ל-100 קק"ל / 15)`, כפול 0.8 למוצר מעל 300 קק"ל ל-100 גרם. לחם / דגן: `0.5 + 0.5·(חלבון ל-100 קק"ל / 4)`, חסום ב-1. ירק: `1 − קק"ל / 120`. פרי: `1 − max(0, קק"ל − 40) / 120`. שומן: טבלה קבועה (שמן 1, טחינה 0.9, אבוקדו 0.8, אגוזים 0.7). אחרת 0.5 | 0..1 | עד כמה המוצר ממלא את הצורך שבגללו הוא נשקל |
| `health` | 0.25 | ציון הבריאות / 10 (0.5 כשאין) | 0..1 | איכות המוצר לפי שמו |
| `history` | 0.20 | `history_score` של המוצר; 0.5 כשאין היסטוריה | 0..1 | הרגל קנייה |
| `price` | 0.15 | נרמול min–max של המחיר ל-100 גרם **בתוך האפשרויות שמושוות כרגע**: הזול ביותר 1, היקר ביותר 0; 0.5 כשיש פחות משני מחירים | 0..1 | זול יחסית לחלופות |
| `variety` | 0.10 | לפי מספר המוצרים מאותו "סוג" שכבר בסל: 0 → 1; 1 → 0.7; 2 → 0.4; יותר → 0.2 | 0.2..1 | סוג חדש בסל |

**מפתח המיון המלא** (לקסיקוגרפי): מוצר "להימנע ממנו" אחרון (רק בבניית סל חלופי) → מזון אהוב קודם → `candidateScore` → ציון בריאות → מחיר ל-100 גרם → שם. מכאן:

- **מזון אהוב גובר על הניקוד כולו.** מוצר אהוב עם ניקוד נמוך ייבחר לפני כל מוצר אחר, בתנאי שהוא נכנס בתקציב.
- אין שוויון לא-מוכרע, ולכן הבחירה דטרמיניסטית.

### שלוש תצפיות על הנוסחה (מניתוח הקוד)

1. **רכיב הגיוון כמעט אינו מבחין.** בצורך החלבון האפשרויות מסוננות מראש לסוגים שאינם בסל, ולכן `variety = 1` לכולן. בירקות, פירות ושומנים, `isDuplicate` כבר מסיר כל מוצר ממשפחה שקיימת בסל, ולכן שוב `variety = 1`. בצורך החלבי כל המועמדים הם מאותו "סוג", ולכן הערך זהה לכולם. הרכיב מבחין בפועל רק בבחירת הדגן השני (דגן מול ירק עמילני) ובתנאי הסף של התוספות האופציונליות.
2. **רכיב ההיסטוריה ניטרלי לכל מועמדי הקטלוג.** למועמד מהקטלוג אין היסטוריה, ולכן הוא מקבל 0.5. הרכיב מבחין רק בין מוצרי ההיסטוריה למוצרי הקטלוג.
3. **בתוך קבוצה הומוגנית הניקוד מתנוון למחיר.** לכל הירקות ציון בריאות 10, וכשאין נתוני תזונה סבירים מהקטלוג כולם מקבלים את אותם ערכי ייחוס. נשארים המחיר והשם.

כלומר, בין מועמדי קטלוג הדירוג נקבע בפועל על ידי `0.30·nutrition + 0.25·health + 0.15·price`. המשקלים 0.20 ו-0.10 פעילים הרבה פחות ממה שהנוסחה מרמזת. כדאי לנסח זאת בזהירות בספר הפרויקט.

**אחרי המנוע:**

- `missingStaples` — לכל צורך יסוד שעדיין חסר, המוצר **הראשון הזמין ברשימת עדיפויות קבועה** (לא לפי ניקוד).
- `missingProtein` — כל עוד תקרת החלבון של הסל נמוכה מ-120% מהיעד, ועד 3 פעמים: המוצר שמעלה את התקרה הכי הרבה. מזון אהוב מנצח בטווח של 5 גרם מהטוב ביותר; היסטוריה מכריעה בטווח של גרם אחד; אחריה המחיר.
- **גיזום תקציב** — כל עוד הסל חורג: מוסר המוצר היקר ביותר בדרגת הגיזום הגבוהה ביותר. הסדר: תוספות אופציונליות → מוצרי היסטוריה → ירקות, פירות וצרכים אחרים → מקורות חלבון → פריטי הקבלה. מוצרי יסוד והשלמת חלבון לעולם אינם מוסרים.

**המינוח המדויק:** *חמדני עם אילוצי כיסוי (מכסות) וסינון היתכנות תקציבי, ואחריו תיקון חמדני (greedy drop).* בפירוט:

- לא דירוג חמדני פשוט — הבחירה מונחית על ידי מכסות, והניקוד מחושב מחדש אחרי כל צעד;
- לא כיסוי קבוצות קלאסי — כמעט כל מוצר מכסה צורך אחד;
- לא תרמיל — התקציב אינו ממוטב אלא נבדק;
- לא סיפוק אילוצים איטרטיבי — אין חזרה לאחור. הגיזום הוא התיקון היחיד.

השלמת החלבון היא חמדנית מסוג אחר: **מקסימום רווח שולי** בכל צעד.

## 4.5 מרחב החיפוש

בחירה של עד A תוספות מתוך P מועמדים: לכל היותר C(P, A) תת-קבוצות. עם P = 55 ו-A = 12 זה כ-4.4·10^11. המכסות מצמצמות מאוד: המרחב האמיתי הוא מכפלת C(n_g, q_g) על פני הצרכים, כאשר n_g הוא מספר המועמדים לצורך g ו-q_g הוא מה שחסר ממנו.

**ניסוח פורמלי אפשרי:** משתנה בינארי x_i לכל מועמד; מקסימום Σ score_i·x_i; בכפוף ל-Σ_{i ∈ צורך g} x_i ≥ q_g לכל צורך, ו-Σ price_i·x_i ≤ התקציב. זו בעיית תרמיל עם אילוצי מכסה (קרובה ל-Multiple-Choice Knapsack). בניסוח הזה הבעיה NP-קשה באופן כללי, כי היא מכלילה את בעיית התרמיל; אך היא NP-קשה רק במובן החלש, וניתנת לפתרון מדויק בתכנות דינמי פסאודו-פולינומי. בגדלים של BetterCart (עשרות מועמדים, תקציב של מאות שקלים) פתרון מדויק היה רץ מיידית.

**הסתייגות:** הניקוד בקוד אינו אדיטיבי לגמרי — `variety` תלוי בסל הנוכחי ו-`price` תלוי בקבוצת האפשרויות. הניסוח הליניארי הוא קירוב, אם כי לפי 4.3 קירוב טוב.

## 4.6 האם החמדני יכול לפספס סל טוב יותר?

כן. שלושה מקרים שנובעים ישירות מהקוד (המספרים להמחשה בלבד):

**מקרה 1 — אין מבט קדימה על התקציב.** נותרו ₪60. צורך החלבון נסרק ראשון: חזה עוף ב-₪45 (ניקוד 0.80) מול ביצים ב-₪14 (ניקוד 0.70). שניהם בתקציב, ולכן נבחר העוף — למחיר יש רק 15% מהניקוד. נותרו ₪15. בהמשך, כשמגיעים לירקות, אף ירק כבר אינו נכנס בתקציב; מאחר שירק אינו מוצר יסוד, נבחר הירק בעל הניקוד הגבוה ביותר *בחריגה*. בסוף הגיזום מסיר את הירקות והפירות (דרגה 3) לפני מקורות החלבון (דרגה 2). התוצאה: סל עם עוף ובלי חלק מהירקות. הצירוף ביצים + ארבעה ירקות היה מכסה יותר צרכים באותו תקציב. זו בדיוק התבנית "A הטוב ביותר לבדו, אבל B + C טובים יותר יחד".

**מקרה 2 — נרמול המחיר תלוי בחלופות.** כשמושוות שתי אפשרויות, הזולה מקבלת 1 והיקרה 0, בין שההפרש הוא 5% ובין שהוא פי עשרה. הפרש מחיר זניח שווה אז 0.15 נקודות ניקוד מלאות — מספיק כדי להפוך הכרעה בין שני מוצרים שהאחד בריא מהשני בנקודה וחצי. ולהפך: הוספת אפשרות שלישית יקרה מאוד מקרבת את שתי הראשונות זו לזו ויכולה להפוך את הסדר ביניהן. זו תלות בחלופות לא-רלוונטיות.

**מקרה 3 — סדר הצרכים קבוע.** הצרכים המאוחרים (פירות, בסיס לבוקר, חלבי) מקבלים את מה שנשאר, הן מהתקציב והן ממכסת התוספות. הם יכולים להיחתך בגלל הסדר ולא בגלל הניקוד.

**עד כמה זה חמור?** לא מאוד. מוצרי היסוד והחלבון מוגנים, פריטי הקבלה מוגנים, והמקרה הראשון מתרחש רק בתקציב צפוף. ואין "אמת מידה" שלפיה סל אחר הוא "טוב יותר" — אין פונקציית מטרה לסל, והמדד האמיתי הוא איכות התפריט שנבנה ממנו.

## 4.7 חלופות

| גישה | מתאימה לבעיה? | הערכה |
|---|---|---|
| החמדני הנוכחי | כן | פשוט, מוסבר (לכל מוצר יש "סיבה"), דטרמיניסטי, מהיר |
| חמדני + שמירת תקציב (מבט קדימה) | כן — השיפור הקטן המתאים ביותר | לפני בחירה לצורך, לשריין את עלות האפשרות הזולה ביותר של כל צורך שעוד חסר. פותר את מקרה 1 בכמה שורות |
| חמדני + חזרה לאחור | חלקית | הגיזום כבר משמש תיקון גס; חזרה לאחור מלאה מסבכת את ההסבר עם תועלת קטנה |
| Beam Search | אפשרי | שמירת w סלים חלקיים במקום אחד מאפשרת לשקול תקציב וכיסוי יחד, ונשארת דטרמיניסטית. דורש פונקציית הערכה לסל שלם — שאינה קיימת כיום |
| תכנות דינמי / תרמיל | אפשרי טכנית | מדויק לניסוח האדיטיבי, בעלות זניחה. אבל ממטב משקלים שלא אומתו, ומאבד את ההסבר "נבחר כי…" |
| כיסוי קבוצות משוקלל | לא ממש | כמעט כל מוצר מכסה צורך אחד, ולכן אין כאן מבנה של כיסוי קבוצות |
| תכנות אילוצים / ILP / MIP | מוגזם | בגודל הזה פתרון מדויק מיידי, אך מחייב ספריית פותר בדפדפן ומקשה על ההסבר |
| Simulated Annealing / אלגוריתם גנטי / Tabu | לא | המרחב קטן והמטרה כמעט אדיטיבית; שיטה מדויקת עדיפה על מטא-היוריסטיקה בכל מדד. אין הצדקה |

**מסקנה:** המגבלה של הסל החכם היא בפונקציית הניקוד (נרמול המחיר, רכיבים שאינם מבחינים) ובהיעדר מדד איכות לסל שלם — לא בשיטת החיפוש. להשאיר כמו שהוא. אם יהיה זמן אחרי ההגשה: שמירת תקציב, ונרמול מחיר מול ייחוס יציב (למשל חציון המאגר של הצורך) במקום min–max של האפשרויות הנוכחיות.

## סיבוכיות

- P — גודל המאגר (עד ~65: 55 מהקטלוג ועוד עד 10 מההיסטוריה); B — גודל הסל; K = 60 סוגי המועמדים; A — מספר התוספות.
- כל צעד: סינון כפילויות O(P·B·K) השוואות מחרוזת, ודירוג O(P·B + P·log P).
- שלב 2: עד A צעדים. שלב 3: עד 4 סבבים × 9 צרכים.
- סך הכול: O((A + 36)·P·B·K) — זניח.
- העלות האמיתית: עד 55 חיפושי קטלוג (כל אחד סריקת `LIKE` על הקטלוג; מטמון של 5 דקות), ועד 5 בניות לסלים החלופיים.

## נקודות חוזק

- דטרמיניסטי לחלוטין, בלי מודל שפה.
- כל מוצר שנוסף נושא סיבה בעברית — האלגוריתם מוסבר מעצם מבנהו.
- אילוצים קשיחים מופרדים מהניקוד ומופעלים לפניו.
- הקבלה של המשתמש היא העוגן: המערכת משלימה ואינה מחליפה.
- מוצרי היסוד והחלבון מוגנים מגיזום, כך שהסל תמיד יכול להזין תפריט.

## נקודות חולשה

- אין פונקציית מטרה או מדד איכות לסל שלם.
- אין מבט קדימה על התקציב; החריגה מתוקנת בדיעבד.
- נרמול המחיר אינו יציב.
- שני רכיבים בנוסחה (גיוון, היסטוריה) כמעט אינם מבחינים בין מועמדי קטלוג.
- מאגר המועמדים קבוע (60 סוגים) ונבחר מוצר אחד לכל סוג — הזול ביותר, לא הטוב ביותר.
- סדר הצרכים ורשימות העדיפויות קבועים בקוד.

## 14. פסאודו-קוד

```
קלט: פריטי_קבלה, היסטוריה, פרופיל, תקציב
פלט: סל

# 1. עוגן
סל ← []
לכל פריט בקבלה שהוא מזון לתפריט:
    אם עובר_סינון_קשיח(פריט, פרופיל) ואינו כפילות בסל: הוסף לסל
לכל מוצר h ב-10 הראשונים בהיסטוריה (עד 5):
    אם h.ציון ≥ 0.72 וגם h.איכות ≥ 0.6 ואינו בסל: הוסף לסל

# 2. מאגר מועמדים
מאגר ← מוצרי היסטוריה שאינם בסל
לכל סוג מועמד c ברשימה הקבועה:
    אם c מותר לפרופיל ואינו בסל:
        מאגר ← מאגר ∪ { המארז הביתי הזול ביותר ל-100 גרם בחיפוש(c) }
מאגר ← { m במאגר : עובר_סינון_קשיח(m, פרופיל) }

# 3. בחירה חמדנית לפי צרכים
נותר ← תקציב − עלות(סל)
לכל צורך g ברשימת הצרכים, לפי הסדר:
    כל עוד קיים(g, סל) < מכסה(g) וגם מספר_התוספות < מקסימום:
        אפשרויות ← { m במאגר : מתאים(m, g) ואינו כפילות בסל }
        אם אפשרויות ריקה: צא מהלולאה
        בתקציב ← { m באפשרויות : מחיר(m) ≤ נותר }
        אם בתקציב אינה ריקה:   נבחר ← ראשון(דרג(בתקציב, g, סל))
        אחרת אם g מוצר יסוד:    נבחר ← הזול ביותר באפשרויות
        אחרת:                    נבחר ← ראשון(דרג(אפשרויות, g, סל))
        הוסף נבחר לסל עם סיבה;  נותר ← נותר − מחיר(נבחר)

# 4. תוספות אופציונליות (עד 4)
חזור עד 4 פעמים:
    נבחר ← הטוב ביותר במאגר שמחירו ≤ נותר, ניקודו ≥ 0.6,
            והוא הרגל חזק או מוצר בריא מסוג חדש לצורך חסר
    אם אין: עצור
    הוסף נבחר לסל

# 5. רשת ביטחון
לכל צורך יסוד שחסר: הוסף את המוצר הראשון הזמין ברשימת העדיפויות שלו
כל עוד תקרת_חלבון(סל) < 1.2 · יעד_חלבון, ועד 3 פעמים:
    הוסף את המוצר שמעלה את תקרת_חלבון הכי הרבה

# 6. גיזום תקציב
כל עוד עלות(סל) > תקציב ויש בסל מוצר שאינו מוצר יסוד:
    הסר את המוצר היקר ביותר בדרגת הגיזום הגבוהה ביותר

החזר סל


דרג(אפשרויות, g, סל):
    לכל m: ניקוד(m) ← 0.30·התאמה_תזונתית(m, g) + 0.25·בריאות(m) + 0.20·היסטוריה(m)
                      + 0.15·מחיר_יחסי(m, אפשרויות) + 0.10·גיוון(m, סל)
    מיין לפי: (להימנע אחרון, מזון אהוב ראשון, ניקוד יורד, בריאות יורד, מחיר עולה, שם)
```
